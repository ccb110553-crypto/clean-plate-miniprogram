API 文档

本系统为「光盘行动」餐食打卡积分系统，后端基于 Node.js + Express + Sequelize 构建，数据库为 MySQL 8.0。

基础信息

开发环境 Base URL：http://localhost:3000/api
生产环境 Base URL：http://<your-server>:3000/api
健康检查：http://localhost:3000/health（无 /api 前缀）
静态资源：/uploads/...（餐盘照片、菜品图、商品图）

概览

统一响应格式

所有接口均返回 JSON，格式统一为：

{
  "code": 0,          // 0 表示成功，非 0 表示失败
  "message": "success",
  "data": { ... }     // 业务数据，失败时为 null
}

认证与鉴权

除公开接口外，均需在请求头携带 JWT：

Authorization: Bearer <token>

JWT 载荷为 { id, role, username }，其中 role 为 student 或 admin。管理端接口额外要求 role === 'admin'。

测试账号：管理员 admin / admin123，学生 student1 ~ student5 / 123456。

认证接口

POST/api/auth/register公开

学生注册，成功后直接返回 token。

参数类型必填说明
usernamestring是用户名（唯一）
passwordstring是密码（至少 6 位）
nicknamestring否昵称，默认等于用户名
studentNostring否学号
classNamestring否班级
dormitorystring否宿舍

响应：data = { token, user }

POST/api/auth/login公开

登录（学生 + 管理员通用）。

参数类型必填说明
usernamestring是用户名
passwordstring是密码

响应：data = { token, user }

// 响应示例
{
  "code": 0,
  "message": "登录成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIs...",
    "user": { "id": 1, "username": "student1", "role": "student", ... }
  }
}
GET/api/auth/me需登录

获取当前登录用户信息（不含密码）。

打卡

POST/api/checkins需登录

提交光盘打卡（上传餐盘照片 + 选择菜品 + AI 预判 + 每日去重 + 防刷限次）。使用 multipart/form-data。

参数类型必填说明
imagefile是餐盘照片（仅图片，≤10MB）
menuIdnumber否关联菜品 ID
mealTypestring否餐次：breakfast / lunch / dinner（默认 lunch）

响应：data = { checkin, aiPreview }。仅当 AI 判为「干净(pass)」时自动通过并发放积分，否则进入人工审核。

GET/api/checkins需登录

我的打卡记录（分页）。

参数类型说明
pagenumber页码，默认 1
pageSizenumber每页条数，默认 10
GET/api/checkins/:id需登录

打卡详情（仅本人）。

积分

GET/api/points需登录

我的积分概览。响应：data = { balancePoints, totalPoints }（可用余额 + 累计获得）。

GET/api/points/logs需登录

积分流水（分页）。query：page、pageSize。

商城

GET/api/products需登录

商品列表（仅上架中，按积分价格升序）。

POST/api/orders需登录

兑换下单（扣积分 + 扣库存 + 生成订单，事务保证原子性）。

参数类型必填说明
productIdnumber是商品 ID

响应：data = order（含 orderNo、pointsCost 等）。

GET/api/orders需登录

我的订单（分页）。

POST/api/orders/:id/cancel需登录

取消订单（仅待处理状态可取消，退还积分）。

挑战

GET/api/challenges公开

挑战活动列表。

POST/api/challenges/:id/join需登录

报名参与挑战。个人挑战以个人为单位，班级/宿舍挑战以队伍为单位。

GET/api/challenges/:id/ranking公开

AI 识别

餐盘剩余量 AI 预判采用三级降级策略（server/src/services/aiService.js）：

优先级方案说明
①百度 EasyDL 自训练三分类模型配置 BAIDU_MODEL_ID 后启用，最准
②百度通用物体和场景识别（advanced_general）次级方案
③本地 sharp 图像启发式算法无外部依赖兜底

统一返回 { score, label, features }：

label含义打卡流转
pass（干净）只剩一点或无残渣✅ 自动通过，发放积分
review（需要审核）不确定⏳ 进入人工审核
dirty（不干净）大量剩菜⏳ 进入人工审核
EasyDL 模型类名需与 aiService.js 中 EASYDL_CLASS_MAP 一致：干净、需要审核、不干净。AI 预判失败不会阻塞打卡提交。
